# Version 5.3.1 — Known Limitations / Go-Live Blockers

This release is a hardened staging build, not a production-ready certification.

## Functionality still incomplete

- Generic backend CRUD is available for the allowlisted master modules, but the existing React UI does not yet provide complete create/edit/soft-delete screens for Property, Owner, Ownership History, Rate, Expense Category, Bank Account, Tenant, Rate Property Mapping, Property Utility, Preventive Maintenance, Gallery, Financial Year and Account Head.
- Invoice generation is wired to the backend for one property at a time. Bulk invoice generation across all eligible flats and automatic invoice PDF storage are not completed.
- Payment proof upload is wired. Owner/property documents, expense voucher, gallery, activity request and notice upload/download screens are not all wired to the private file API.
- Notice creation API is available, but the current screen flow is not wired to it.
- Full `getReports` API, audited balance sheet journal posting and server-side financial statement generation are not completed.
- `getDashboardSummary` exists but the dashboard currently calculates its display from selectively loaded modules. Six-month collection trend now derives from actual invoice/confirmed receipt records; it shows zero when no records exist.
- User Management still uses the existing Central Master APIs. Society-side `User Master & Role Management` CRUD is not exposed generically.

## Accounting/data constraints

- Ownership-based invoice generation requires exactly one ownership-history row to cover the entire billing period. If a transfer occurs mid-period, split the billing period. Joint ownership with multiple overlapping ownership rows is rejected pending a documented allocation rule.
- Resident payment submissions are limited to the current ownership row. Admin/Accountant may record payment against an older ownership period.
- Confirmed paid expenses cannot be cancelled. A reversal/credit-note workflow is not implemented.
- Generic soft-cancel maps status to inactive/archived/vacated/cancelled. It does not physically delete records.
- Google Sheets does not support atomic transactions across Invoice, Receipt, Allocation and Bank Account sheets. `LockService` serializes this code's writes and `_Operation Ledger` records `STARTED`/`DONE`, but a runtime/quota failure after some sheet writes can leave partial state. Manual reconciliation is required; no automatic rollback worker exists.
- `requestId` is retained for exact in-session retries. A retry after browser refresh may create a new request ID; business duplicate checks cover some actions (payment reference, invoice period, expense reference) but not every generic master record.

## Security/performance constraints

- Central Master lookup reads only the society-code column and matching rows, but still revalidates user status on every protected request.
- Unfiltered non-Resident module reads use range pagination. Resident/property-filtered reads scan the property key column and fetch matching rows. Notice/gallery visibility scans their respective sheets.
- Frontend loads all pages of the selected module; server pagination exists, but user-controlled page navigation/infinite loading is not yet implemented in every screen.
- Session tokens are still held in browser localStorage in the existing app. This is vulnerable to theft if an XSS issue is introduced; use a strict CSP and consider an HttpOnly-cookie backend before higher-risk deployment.
- Apps Script Web App is deployed with public endpoint access for GitHub Pages; all protected actions rely on server-side token/role checks. Apps Script/Sheets quotas and runtime limits apply.
- Audit Log cannot be changed through app CRUD APIs, but a Google Sheet owner/editor can still modify it directly outside the app.
- Drive file access is checked against `_File Registry`, society folder ancestry, role and property. All document types still need live permission tests. Small files are returned as Base64; streaming download is not implemented.

## Verification still required by owner

- Confirm exact tab names and headers in a disposable test society database.
- Set Apps Script Script Properties and authorize Spreadsheet, Drive and Mail services.
- Test Admin, Committee, Accountant and Resident accounts, including inactive account revocation and cross-society access.
- Test current/previous owner, joint ownership and ownership transfer periods.
- Test payment partial allocation, advance, duplicate reference, duplicate request ID and interrupted operation recovery.
- Test expense approval with insufficient funds and duplicate click.
- Test private KYC/payment proof/document access from different society and role accounts.
- Test backup copy, manual Central Master backup and restore from a copy (never overwrite the only live database).
- Run `npm install`, `npm test`, `npm run lint`, `npm run build`, then GitHub Pages browser tests on the owner's machine/repository.
