# ABAS SATHI Version 5.4 — Source Audit & Changelog

## Architecture inspected
- Frontend: React + TypeScript + Vite.
- Backend: Google Apps Script Web App (`apps_script/Code.gs`).
- Database: Central Master + society-specific Google Sheets.
- Files: private society folders in Google Drive.
- Hosting/deployment: existing GitHub workflow/configuration retained.

## Findings
1. Login form did not remember non-secret identifiers and had only basic submit feedback.
2. `authRequest` assumed every response was JSON and did not support a bounded request timeout.
3. Persisted local session was trusted by the initial App render until a later API request failed.
4. `findRowsByHeaderValue_` fetched matching sheet rows one by one, creating N+1 Spreadsheet service calls in login and every protected request.
5. Generic write actions already had a request-ID operation ledger; frontend preserved request IDs after failures but did not automatically retry safe transient network failures.
6. File upload validated related record/module/target field after creating the Drive file and writing its registry row. Validation is moved before file creation.
7. Resident payment proof was uploaded before the payment record existed, leaving no direct record link. It is now uploaded and linked using the confirmed Transaction_ID.

## Modified files
- `src/components/auth/Login.tsx` — quick login UI, remember Society Code/Login ID only, password visibility, single-submit lock, progress and validation.
- `src/utils/authClient.ts` — request timeout option, robust JSON parsing, typed retryable transport errors, no-store requests.
- `src/App.tsx` — server validation of restored sessions before mounting protected UI; refresh session expiry/profile.
- `src/context/AppContext.tsx` — one safe retry with same requestId for operation-ledger-backed actions; client-side sliding expiry.
- `apps_script/Code.gs` — batch lookup, batched header extension, sliding session TTL, preflight validation for Drive upload links.
- `src/components/common/Header.tsx` — start server-side logout revocation before navigation, using configured/default backend URL.
- `src/components/settings/DocumentCenter.tsx` — explicit private Drive upload/linking progress feedback.
- `src/components/payments/PaymentsView.tsx` — submit payment first, then attach proof to the saved transaction; prevent double submit.
- `src/components/requests/ActivityRequestsView.tsx` — prevent duplicate request submission and show progress.
- `src/components/expenses/ExpensesView.tsx` — prevent duplicate expense submission and show progress.
- `package.json` — version 5.4.0.
- `metadata.json`, `README.md` — release metadata.

## No schema change
No existing business sheet, column, key, financial formula or role has been renamed or removed. Existing internal `_Operation Ledger` and `_File Registry` continue to be used.

## No files deleted
No source file or existing application module was deleted.
