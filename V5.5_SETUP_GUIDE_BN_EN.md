# ABAS SATHI Version 5.5 — Authentication Upgrade

**App:** ABAS SATHI (আবাসসাথী)  
**Tagline:** Smart Living. Better Community.  
**Base:** Version 5.4.2  
**Target:** Version 5.5.0

## What changed

### Login experience
- Mobile-first responsive sign-in layout using the existing forest-green / warm-cream brand palette.
- Society Code, Login ID and Password remain the only sign-in credentials.
- Accessible labels, input icons, focus states, show/hide password, loading state and bilingual labels/messages.
- Returning users have their remembered Society Code and Login ID populated and the password field focused.
- `Clear Saved Login` removes the remembered identifiers from the current browser.
- Unchecking Remember Me immediately removes remembered identifiers.
- The app never stores the password in localStorage, sessionStorage or cookies.
- Remembered identifiers are written only after a successful login and only when Remember Me is enabled.

### Authentication and session
- Successful login is followed by a second server-side `getMyProfile` validation before protected pages mount.
- Restored sessions are checked against the server. Protected pages do not mount when validation fails.
- Invalid/expired sessions are cleared. Temporary network/server errors keep the token locally but show a retry/sign-out screen; the app does not trust a cached token alone.
- Server login responses use a common error for unknown/inactive society, unknown/inactive user, missing password hash and incorrect password.
- Login attempt counters expire after 15 minutes; they do not permanently disable accounts.
- Each successful login creates an independent random session token. A new device login does not invalidate another device token.
- Existing six-hour server-side sliding TTL and per-request account/role revalidation are preserved.
- Existing password hash format and legacy SHA-256-to-iterated-HMAC upgrade are preserved.

### Forgot Password
- Existing Apps Script MailApp OTP workflow retained.
- OTP validity remains 10 minutes; backend permits up to five incorrect OTP attempts.
- UI adds resend cooldown, six-digit OTP input, password strength validation and password confirmation.
- No paid SMS/email provider or external API has been introduced.

### Responsive behaviour
- Uses `100svh` / `100dvh`, safe-area insets, scrollable mobile layout and landscape handling.
- Viewport metadata opts into keyboard-driven content resizing where supported.
- Inter and Noto Sans Bengali remain the app fonts.

## Deployment guide

### Frontend (GitHub / static hosting)
1. Back up the currently deployed Version 5.4.2 source and note the current Git commit.
2. Replace the repository files with the complete Version 5.5 source archive.
3. Keep the existing Apps Script URL and Central Master configuration. No new frontend secret is required.
4. Run:
   ```bash
   npm install
   npm run lint
   npm test
   npm run build
   ```
5. Fix any environment-specific build errors before deploying.
6. Deploy the generated `dist` folder using the existing GitHub Pages / hosting workflow.
7. Test the website over HTTPS on desktop and mobile browsers.

### Google Apps Script
1. Open the existing Apps Script project attached to the Central Master.
2. Back up the current `Code.gs`.
3. Replace its contents with `apps_script/Code.gs` from this release.
4. Confirm Script Properties still contain `CENTRAL_MASTER_SPREADSHEET_ID` and the existing required configuration.
5. Run the existing `authorizeRequiredServices` helper as the project owner if MailApp/Drive/Sheets scopes need authorization. This helper checks service access and does not send a test OTP.
6. Deploy > Manage deployments > Edit the existing Web App deployment > select **New version**.
7. Keep execution as the deployment owner and access set to **Anyone**, as required by the existing static frontend architecture.
8. Keep the deployed `/exec` URL unchanged where possible. If Google creates a different URL, update the app's backend URL configuration.
9. Test `ping`, login, `getMyProfile`, logout and password reset using a non-production test account.

## Forgot Password delivery configuration

The existing OTP workflow uses Google Apps Script `MailApp.sendEmail`; no paid third-party API was added. The Apps Script owner must authorize MailApp and the Google account must have remaining daily email quota. If the project is not authorized, email quota is exhausted, or the registered email is incorrect, OTP delivery may fail. The UI does not claim that an OTP was sent unless the Apps Script endpoint returns success. The backend response is deliberately generic to reduce account enumeration.

## Session and device behaviour

- Session tokens are held in the existing `abasSathiSession` localStorage record on that browser profile.
- Remember Me stores only Society Code and Login ID in `abasSathiRememberedLogin`.
- Different devices/browser profiles have separate local storage and receive separate session tokens.
- Logging out removes the current token from Apps Script cache and clears the local session.
- Existing sessions on other devices are not revoked by a new login or by logging out from one device.
- The existing design does not provide a remote device/session management screen.

## Security notes / known constraints

1. Apps Script `CacheService` is the existing session store and is subject to Google cache behaviour/eviction. A six-hour TTL is preserved, but CacheService is not a durable session database.
2. Rate limiting uses Apps Script CacheService with a 15-minute expiry. It is a practical best-effort control, not a WAF-grade distributed rate limiter.
3. The current backend uses `MailApp` for OTP. It requires Google authorization and is subject to quota.
4. The app uses the same deployment-wide Apps Script endpoint and per-society `Database_ID` routing. The existing Central Master and society isolation logic are unchanged.
5. This release does not add persistent-login tokens, device fingerprinting, remote session revocation, MFA, or new database columns.
