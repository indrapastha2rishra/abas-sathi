# ABAS SATHI v5.3 — API Reference (incremental)

All protected requests use POST with JSON body and `Content-Type: text/plain;charset=utf-8`.

## Common request

```json
{"action":"getModuleData","token":"<token>","module":"properties","page":1,"limit":50}
```

## Common success response

```json
{"status":"success","module":"properties","data":[],"pagination":{"page":1,"limit":50,"total":0,"totalPages":0}}
```

## Current read actions

| Action | Required fields | Notes |
|---|---|---|
| `getModuleData` | `token`, `module` | Paginated read; `page` defaults to 1; `limit` defaults to 50 and is capped at 200. Optional `search`, `status`, `propertyId`, `ownerId`, `fromDate`, `toDate`. |
| `getDashboardSummary` | `token` | Operational counts and limited recent activity; not an audited financial report. |
| `getSocietyData` | `token` | Compatibility bulk read for existing v5.2 UI. Avoid for new screens. |

## Module keys

`properties`, `owners`, `ownershipHistory`, `tenants`, `rates`, `invoices`, `receipts`, `billWiseDetails`, `expenses`, `expenseCategories`, `bankAccounts`, `activityRequests`, `notices`, `gallery`, `preventiveMaintenance`, `propertyUtilityDetails`, `financialYears`, `accountHeads`.

## Authorization currently applied to read endpoints

- Bank Account Master: Admin and Accountant only.
- Expense, Expense Category and Account Head: Resident denied.
- Resident property data: filtered to the authenticated `PropertyID` for property-bound modules.
- Resident owners: derived from ownership rows for their property.
- Resident activity requests: own property and requester identity only.
- Resident notices/gallery: All Residents or Selected Properties visibility only.
- User Master and Audit Log: excluded from bulk client payload.

## Important implementation limitations

- These are read endpoints only. Do not infer that matching write APIs exist.
- Status and date filters use module-specific header mappings for the principal registers. Confirm exact live spreadsheet headers before relying on them; an unrecognized optional field returns no matching rows rather than inferring another column.
- Bulk compatibility action is retained for the existing UI and is not the desired final performance architecture.
- Error responses still use the existing simple `{status:"error", message:...}` envelope in several legacy paths; request IDs and structured error codes are not yet universal.
