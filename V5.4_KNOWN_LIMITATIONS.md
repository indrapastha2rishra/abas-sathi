# Version 5.4 — Known Limitations

1. No access to the user's live Google account, Apps Script deployment, Central Master, society spreadsheets or Drive folders was available for this source upgrade.
2. True atomic transactions spanning Google Sheets and Google Drive are not available. The backend uses operation-ledger idempotency and pre-validation, but partial service failures may still require manual reconciliation.
3. Fetch does not expose upload byte progress for this cross-origin Apps Script flow. The UI can display a processing state, not a reliable percentage.
4. The existing browser session token remains in localStorage for backward compatibility. It is not an HttpOnly cookie; browser-accessible token exposure remains a concern if an XSS vulnerability exists.
5. The backend revalidates account status and role for every protected request. This is intentionally retained for security and still requires a Central Master read; the batch-read optimization reduces service calls but does not remove this authorization check.
6. Full build and live tests must be completed in the deployment environment. No production-readiness claim is made by this source package.
