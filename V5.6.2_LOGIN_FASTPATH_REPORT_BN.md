# ABAS SATHI v5.6.2 — Login Fast-Path Report (বাংলা)

## লক্ষ্য
Sign In থেকে authenticated Dashboard shell যত দ্রুত সম্ভব দেখানো। **১ সেকেন্ড target একটি লক্ষ্য, Apps Script/Sheets/network latency-র কারণে guarantee নয়।** এই patch authentication bypass, password caching বা password KDF কমায় না।

## v5.6.1-এ পুনরায় audit-এর findings
- Login-এ Society Master ও Society User Access-এর header reads এবং TextFinder-based lookups ছিল।
- Password verification current credential-এর জন্য 12,000 HMAC-SHA256 iterations; এটি login-এর CPU-heavy অংশ এবং security setting কমানো হয়নি।
- Successful login response-এর আগে Last_Login sheet write হচ্ছিল।
- Login-এর পর প্রথম protected API request-এ server profile cache miss হলে Central Master user rows পুনরায় scan করতে পারত।
- Frontend login সফল হলে AppContext dashboard data load শুরু করে; dashboard modules login-এর critical path নয়, কিন্তু initial widgets data আসা পর্যন্ত empty/loading থাকতে পারে।

## v5.6.2 পরিবর্তন
1. Auth sheet headers Script Cache-এ 5 মিনিট; cache-এ শুধু header/schema, credential নয়।
2. Society ও Login_ID exact TextFinder matching; Society_Code এবং Active status server-side যাচাই করা থাকে।
3. Login_ID candidates-এর row span ছোট হলে একবারে batch row read; large span-এ wide read এড়িয়ে candidate rows আলাদাভাবে পড়া।
4. Successful login response-এ Last_Login update blocking write বাদ; token-validated `updateLoginActivity` metadata action frontend fire-and-forget-এ চালায়। Row identity, Society_Code, account status revalidate করে write.
5. Login-এর সময় validated public profile (password/hash fields ছাড়া) 30-second server cache-এ রাখা; first Dashboard API-তে Central Master user lookup এড়াতে। Role/status change-এর existing cache invalidation behavior বজায়.
6. Frontend successful authentication-এর পর session persist করে, background Last_Login update শুরু করে, সঙ্গে সঙ্গে `onLogin(session)` দিয়ে app shell mount করে।

## Security & compatibility
- Password hash / salt frontend-এ পাঠানো হয় না এবং cache-এ রাখা হয় না।
- 12,000 HMAC iteration setting অপরিবর্তিত; KDF bypass বা fallback নেই।
- Society Code, Login_ID, active account, role/session, token validation অপরিবর্তিত।
- Database sheet names/columns, business calculations, roles এবং UI design বদলানো হয়নি।
- Last_Login field update asynchronous; failure হলে login flow block করে না।

## Verification
- Apps Script source JavaScript syntax: `node --check` PASS.
- Frontend production build / TypeScript: dependencies এই workspace-এ ইনস্টল নেই; test/build চালানো যায়নি।
- Live Apps Script/Google Sheets login এবং cold-start timing: এখানে credentials/deployment access নেই; not tested.
- 1-second target: not measured; not certified.

## Limitation / strategic recommendation
Apps Script cold-start, spreadsheet service latency, network, redirect, and the 12,000-round KDF make a reliable sub-1-second end-to-end sign-in unrealistic to guarantee. If a strict 1-second SLA is mandatory, migrate password authentication to a managed identity provider (Firebase Authentication is a possible free-tier option) and keep Apps Script as the apartment-data API behind verified auth tokens. This requires a controlled credential migration and backend token verification; it must not be improvised as a frontend-only shortcut.
