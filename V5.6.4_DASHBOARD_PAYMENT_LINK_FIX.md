# V5.6.4 Dashboard & Payment Register Corrections

## Implemented
1. Dashboard Collection Rate: issued invoice totals exclude cancelled/draft/pending approval invoices; paid amounts use confirmed receipt transactions allocated in Bill Wise Details. Legacy invoices without allocation rows fall back to `Paid_Amount`.
2. Maintenance Status: paid/partial/unpaid/overdue counts derive from the same allocation-backed invoice metrics rather than stored stale status values.
3. Outstanding dues: allocation ledger only from confirmed receipt transactions reduces invoice balance; non-issued/cancelled invoices excluded.
4. Resident Payment History & Receipts: dashboard list sorts by received date descending and receipt preview is only offered for confirmed receipts with receipt number (pending entries remain labelled awaiting verification).
5. Resident Billing Summary: issued count and paid/overdue counts use computed invoice metrics; pending verification is counted from pending receipt records.
6. Receipt Register and 7. Bill-wise Allocation: existing PaymentsView remains wired to AppContext `receipts` and `billAllocations`, sourced from Fund Inflow Register and Bill Wise Details; this patch keeps those direct data sources and aligns dashboard calculations with them.

## Data semantics
- Confirmed receipt records only count toward paid/allocation dashboard metrics.
- Allocations are grouped by InvoiceID and summed only when Transaction_ID belongs to a Confirmed receipt.
- For invoice rows without allocations, Paid_Amount is the compatibility fallback.
- Dashboard issued invoice calculations exclude Cancelled, Draft, Pending_Approval and Pending Approval.
- This UI patch does not change Apps Script schemas or introduce new sheet names.
