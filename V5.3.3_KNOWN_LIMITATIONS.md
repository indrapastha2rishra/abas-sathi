# Version 5.3.3 — Known Limitations & Production Gates

1. No live Google Apps Script deployment, live Google Sheets reads, private Drive operations or GitHub Pages browser session were available for this source build.
2. Full Vite production build and actual React/Vite type-check were not run because project dependencies are not installed in the build environment. `tsc --noEmit` stops at missing `vite/client`.
3. TS/TSX syntax transpilation passed for 32 source files; this does not replace the real dependency-aware TypeScript build.
4. The existing calculation tests passed 9/9 using a temporary transpile runner; the new Ownership-wise Outstanding tests passed 2/2. The project's `npm test` command itself was not run because `tsx` is not installed.
5. Ownership-wise Outstanding uses `Ownership_ID` persisted on each Invoice_Register row. It does not infer an Ownership_ID from billing dates. Blank or invalid links are displayed as `Not linked` / `Needs review`; authorized staff must reconcile them.
6. If the same Ownership_ID is mistakenly reused across owners or periods, the report will group those invoices together. Maintain unique Ownership_ID values for each distinct ownership period.
7. The property area display uses the source-mapped fields. Legacy `Super Buildup Area` is treated as `Structural_Area`; `Super Built-up Area` is treated as `Super_Built_up_Area`. Verify actual sheet headers and sample values before launch.
8. Existing 5.3.2 accounting limitations remain: historical journal backfill is not automatic; partial multi-sheet writes require manual reconciliation; backup retention and Central Master restore need operational procedures.
9. No independent accounting audit or cross-society penetration test was performed.
10. Complete `MIGRATION_V5.3.2_TO_V5.3.3_BN.md` staging acceptance tests before using the release with live financial data.
