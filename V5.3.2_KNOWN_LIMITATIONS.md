# Version 5.3.2 — Known Limitations & Production Gates

1. **Live integrations not executed here.** No owner Google account authorization, live Central Master, society database, Drive folder or deployed Apps Script URL was available for integration testing.
2. **Production build not run.** `npm install` timed out in this environment; `node_modules` is not present. `npm run build` and the project's real `npm run lint` were not completed.
3. **Type checking qualification.** TS/TSX syntax was transpiled for all source files. A stub-assisted TypeScript semantic check passed, but this is not equivalent to compiling against the actual React/Vite dependency declarations.
4. **Apps Script quotas.** Trigger runs and Drive copies are subject to Google Apps Script quotas, daily Drive limits and execution time. Monitor `_Backup Run Log`.
5. **No backup retention policy.** Daily backups accumulate. Set a retention policy and verify at least one restore before deleting older backups.
6. **Society restore only.** Automated backup includes Central Master, but the restore UI currently restores a society database only. Central Master restore must be handled manually by the owner using its verified Drive backup.
7. **Restore is not a full filesystem rollback.** It replaces sheets that exist in the backup; newer internal tabs absent from that backup may remain. Compare all sheet names, headers, hidden states and records after restore.
8. **Operation recovery is review-assisted.** The app lists incomplete `STARTED` operations but does not auto-complete or auto-rollback partial multi-sheet writes. Reconcile target registers and audit records before retrying.
9. **Journal migration.** Only transactions created by Version 5.3.2 journal-aware endpoints post to `_Journal Ledger`. Historical invoices, receipts and expenses are not backfilled. Prepare one balanced opening-balance batch from reconciled opening bank balances, receivables, advances, liabilities and equity.
10. **Balance Sheet is not an independent audit.** Snapshot SHA-256 verifies the saved payload was not altered through the app's approval workflow. It does not prove source documents, balances or accounting treatment were independently audited.
11. **Opening balance correction.** Only one opening balance batch is accepted. Corrections require a reviewed adjustment journal; no adjustment-journal UI is included.
12. **Upload size.** Private Drive upload/download is Base64-based and capped at 5 MB. Large files require a different upload transport.
13. **Document relation headers.** Related document linking expects existing columns such as `Owner_Document`, `File_Reference`, `Photo_File_Reference`, `Attachment`, or the listed file ID columns. If a society's sheet uses different headers, update the mapping before using the link field.
14. **Report account mapping.** Journal entries use system account names and account types. Confirm account classifications with the society accountant before relying on the Balance Sheet.
15. **Multi-society test.** Cross-society security has not been tested against two live society spreadsheets. Perform SO001/SO002 isolation tests before launch.
