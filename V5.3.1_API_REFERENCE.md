# ABAS SATHI Version 5.3.1 — API Reference

All authenticated actions use POST JSON with `Content-Type: text/plain;charset=utf-8`. Do not put tokens in URLs. Every protected request uses a token issued by `login`; the backend revalidates the user's active status and role against Central Master.

## Read actions

- `getModuleData`: `module`, optional `page`, `limit` (max 200), `search`, `status`, `propertyId`, `ownerId`, `fromDate`, `toDate`.
- `getDashboardSummary`: dashboard aggregate response; not an audited financial statement.
- `getSocietyData`: disabled; returns `SELECTIVE_READ_REQUIRED`.

Module keys: `properties`, `owners`, `ownershipHistory`, `tenants`, `rates`, `invoices`, `receipts`, `billWiseDetails`, `expenses`, `expenseCategories`, `bankAccounts`, `activityRequests`, `notices`, `gallery`, `preventiveMaintenance`, `propertyUtilityDetails`, `financialYears`, `accountHeads`, `ratePropertyMapping`, `auditLogs`.

## Financial actions

All write actions require a unique `requestId` (at least 12 characters) and are serialized with `LockService`.

- `generateInvoice`: `propertyId`, `rateId`, `billPeriodFrom`, `billPeriodTo`, `dueDate`, optional `quantity`, `lateFee`, `discount`, `adjustment`, `remarks`.
- `submitPayment`: creates a Pending Verification record with a transaction ID; the official `Receipt_Number` is assigned only after confirmation. `propertyId`, `ownershipId`, `ownerId`, `amount`, `mode`, `reference`, optional `bankAccount`, `remarks`, `fileReference`, `invoiceIds`. Resident payments are restricted to the authenticated user's linked property and current ownership.
- `confirmPayment`: `transactionId`, optional `allocations:[{invoiceId,amount}]`. Only Admin/Accountant. An empty allocation list leaves the confirmed funds unallocated as advance.
- `rejectPayment`: `transactionId`, `reason`. Only Admin/Accountant.
- `allocatePayment`: currently delegates to the confirmation/allocation workflow; do not call it for already-confirmed receipts.
- `createExpense`: `record` with expense fields. Creates Pending Approval.
- `approveExpense`: `expenseId`. Current UI action performs guarded approval-and-payment for Admin/Accountant.
- `markExpensePaid`: `expenseId`. Only Approved expenses can be paid through this action; Admin/Accountant.
- `cancelExpense`: `expenseId`, `reason`. Paid expenses cannot be cancelled; use a separately documented reversal entry.

## Generic master/non-financial actions

- `createRecord`: `module`, `record`.
- `updateRecord`: `module`, `recordId`, `record`.
- `cancelRecord`: `module`, `recordId`, `reason`. Soft cancellation only when the target sheet has a supported status column. There is no physical delete API.

Write-enabled modules: properties, owners, ownershipHistory, rates, expenseCategories, bankAccounts, activityRequests, notices, gallery, preventiveMaintenance, ratePropertyMapping, propertyUtilityDetails, financialYears, tenants, accountHeads. Role allowlists are enforced in `CRUD_MODULES` in `Code.gs`.

## Private file actions

- `uploadPrivateFile`: `fileName`, `mimeType`, `base64`, `category`, optional `propertyId`, `ownerId`. PDF/JPG/PNG, max 5 MB. Returns Drive `fileId`.
- `getPrivateFile`: `fileId`, optional `propertyId`. File must be in the society-specific private folder and registered in `_File Registry`.

The API currently returns small file content as Base64 for download/preview; max 5 MB. A streaming download endpoint is not implemented.

## Backup

- `createSocietyBackup`: Admin-only copy of the authenticated society spreadsheet to the private society Drive folder.
- `backupCentralMasterManual()`: run manually by Apps Script owner; not exposed to society users.

## Internal tabs

- `_Operation Ledger`: hidden idempotency/recovery records. `STARTED` means an operation may have partially written; reconcile affected sheets before retry.
- `_File Registry`: hidden mapping from file ID to society/property/owner/category.

## Limitations

Google Sheets does not provide cross-sheet ACID transactions. Locks prevent simultaneous execution of these Apps Script handlers, but cannot guarantee rollback after a runtime/quota failure between sheet writes. Generic CRUD APIs exist, but not all modules have complete create/edit forms wired in the React UI. See `V5.3.1_RELEASE_NOTES_BN.md` and `V5.3.1_TEST_REPORT.md`.
