# ABAS SATHI v5.5.1 – Year-End Closing & Carry Forward

## Added
- Admin Reports submenu: Year-End Closing & Carry Forward.
- Server-side Fund Balance Register creation and schema extension.
- Preview by Financial Year, account-wise Cash/Bank reconciliation, and Admin finalization.
- Finalized closing balances carry forward as next FY opening balances.
- Dashboard opening fund balance now reads from Fund Balance Register via authenticated Apps Script API; current FY receipts and paid expenses are read from Fund Inflow Register and Expense Register.
- Audit log, script lock, idempotency ledger, role checks, and finalization safeguards.

## Accounting rule
Opening Balance + Confirmed Receipts - Paid Expenses = Closing / Available Fund. Opening is never counted as a new receipt. Transactions with unmapped non-cash Bank_Account values must be corrected before finalization. Actual closing balances must reconcile to the system calculation.

## Important deployment notes
1. Deploy the updated `apps_script/Code.gs` as a new Apps Script Web App version.
2. Ensure each society database has Financial Year Master, Fund Inflow Register, Expense Register, and Bank Account Master with the field names used by the app.
3. The first financial year uses Bank Account Master.Opening_Balance as initial bank opening and Admin enters the initial physical cash opening in the Year-End Form. Verify all initial figures before use.
4. Finalization is permitted only after the selected FY End_Date has passed. Previous FY must already be finalized.
5. Confirmed receipts are included only when Receipt_Status is Confirmed; expenses only when Expense_Status is Paid. Cash is assigned by Payment_Mode / Received_Mode = Cash. Non-cash transactions must map to a Bank Account Master record by BankAccount_ID, Account_Name, Bank_Name or Account_Number.
6. Finalized rows are locked by application logic; corrections require controlled admin-led correction to source records and a separately audited adjustment process. Do not manually edit finalized rows in Sheets.

## Validation status
Source-level syntax and static checks are provided with this package. A live Google Apps Script deployment, real society spreadsheet, bank reconciliation, and role/session integration test are still required before production use.
