# ABAS SATHI Version 5.3.2 — API Reference

All protected actions are POST requests to the Apps Script Web App. Payload includes `token`. Frontend uses `Content-Type: text/plain;charset=utf-8` to avoid unnecessary preflight. Responses are JSON with `status: success|error`.

## Master Data
- `getModuleSchema` `{module}` → allowed editable headers and ID field.
- `getModuleData` `{module,page,limit,search,status,propertyId,ownerId,fromDate,toDate}` → paginated data.
- `createRecord` `{module,record,requestId}`.
- `updateRecord` `{module,recordId,record,requestId}`.
- `cancelRecord` `{module,recordId,reason,requestId}` → soft archive/cancel only. Owner Master is marked `Owner_Status=Inactive` (the backend appends this column if missing); an owner with current ownership cannot be archived. Ownership History uses this action to set `Ownership_Status=Previous` and `Ownership_End_Date` to the current date; history rows are never deleted.
- `adminUpdateUser` `{userId,updates}`.
- `adminSetUserStatus` `{userId,status:"Active"|"Inactive"}`.
- `adminApproveUser`, `adminRejectUser`, `adminSetKycStatus` remain available.

Generic CRUD module keys:
`properties`, `owners`, `ownershipHistory`, `rates`, `expenseCategories`, `bankAccounts`, `activityRequests`, `notices`, `gallery`, `preventiveMaintenance`, `ratePropertyMapping`, `propertyUtilityDetails`, `financialYears`, `tenants`, `accountHeads`.

Financial registers use dedicated endpoints, not generic CRUD:
- `generateInvoice`, `cancelInvoice`
- `submitPayment`, `confirmPayment`, `rejectPayment`, `allocatePayment`
- `createExpense`, `approveExpense`, `markExpensePaid`, `cancelExpense`

## Documents
- `uploadPrivateFile` `{fileName,mimeType,base64,category,propertyId?,ownerId?,relatedModule?,relatedRecordId?,requestId}`.
- `listPrivateFiles` `{category?,limit?}`.
- `getPrivateFile` `{fileId,propertyId?}` → authorized Base64 response, max 5 MB.
- Existing KYC endpoints: `uploadKycDocument`, `adminSetKycStatus`.

Allowed document categories are enforced on the server:
- Admin: all configured categories.
- Committee: Gallery Photo, Notice Attachment, Activity Request Attachment.
- Accountant: Expense Voucher, Payment Proof, Invoice PDF, Activity Request Attachment.
- Resident: Payment Proof and Activity Request Attachment; resident reads are property/ownership scoped. Resident may download only their own KYC file.

If `relatedModule` and `relatedRecordId` are supplied, file linking is attempted against the module's known reference column. If the relevant sheet does not contain one of the documented reference fields, upload is not a successful linked attachment; add the expected field or upload without relation and reconcile the registry.

## Backup and recovery
- `createSocietyBackup` → manual society spreadsheet copy.
- `configureAutomatedBackup` `{enabled:boolean}` → daily time trigger, approximately 02:00 Apps Script timezone.
- `listSocietyBackups` → same-society backup registry.
- `listRecoveryOperations` → Admin-only list of `STARTED`/`RECOVERY_REQUIRED` operations for manual reconciliation.
- `restoreSocietyBackup` `{backupFileId,requestId}` → pre-restore backup, validates same-society registry and Drive folder, replaces sheets present in backup.
- `listRecoveryOperations` → Admin-only `_Operation Ledger` STARTED/RECOVERY_REQUIRED queue.
- Trigger handler `runScheduledSocietyBackups` copies Central Master and active society databases.

## Reports and accounting
- `getReports` `{reportType,fromDate?,toDate?,asOfDate?}`.
  - `receiptPayment`
  - `financialYear`
  - `outstanding`
  - `ownerOutstanding`
  - `expenseSummary`
  - `balanceSheet`
- `postOpeningBalances` `{entries:[{accountCode?,accountName,accountType,debit,credit}],effectiveDate,requestId}`. Admin only. Account types: Asset, Liability, Equity, Fund. One opening batch only.
- `createReportSnapshot` `{reportType:"Balance Sheet",asOfDate,remarks}`. Admin/Accountant.
- `listReportSnapshots` → Admin/Accountant snapshot metadata, payload omitted.
- `approveReportSnapshot` `{snapshotId}`. Admin only; creator cannot approve own snapshot.

## Journal posting rules
- Invoice: Dr Accounts Receivable; Cr `<Purpose> Income`.
- Confirmed payment: Dr Bank; Cr Accounts Receivable for allocated amount; Cr Resident Advances for unallocated amount.
- Paid expense: Dr `Expense: <Expense_Category>`; Cr `Bank: <Bank_Name>`.
- Unpaid invoice cancellation: reverse income and receivable.
- Opening balances: one balanced debit/credit batch. Use exact account names for system accounts that later postings use: `Accounts Receivable`, `Resident Advances`, `Bank: <Bank_Name>`, `Expense: <Expense_Category>`, and `<Purpose> Income`. `Fund` opening accounts are included with equity in the Balance Sheet calculation.

The Balance Sheet report groups journal rows by account type. It is an internal system report, not a statutory audit opinion. Existing historical transactions are not automatically backfilled.
